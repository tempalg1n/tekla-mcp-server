# Tekla MCP Server

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![CI](https://github.com/tempalg1n/tekla-mcp-server/actions/workflows/ci.yml/badge.svg)](https://github.com/tempalg1n/tekla-mcp-server/actions/workflows/ci.yml)

[MCP](https://modelcontextprotocol.io/)-сервер, который подключает ИИ-ассистентов к моделям **Tekla Structures** через [Tekla Open API](https://developer.tekla.com/doc/tekla-structures/2026/tekla-structures-64304).

Задавайте вопросы о металлоконструкциях на естественном языке — вес, количество, материалы, профили, выделение — и ассистент запросит данные из открытой модели.

> **Статус: активная разработка (v0.8.0).** Сервер собирается и работает на Windows, проверен на живых моделях Tekla 2021 и 2023. Сборки под Tekla 2024–2026 компилируются, но не проверены — нужны тестировщики. Набор инструментов расширяется; API и поведение могут меняться между релизами. См. [Известные ограничения](#известные-ограничения) и [Дорожную карту](#дорожная-карта).

**Языки:** [English](README.md) · Русский (этот файл)

## Зачем этот проект

Tekla Structures хранит богатые BIM-данные — детали, сборки, веса, классы, пользовательские атрибуты — но доступ к ним возможен только через Windows-only .NET API. ИИ-ассистентам нужен структурированный и безопасный мост для чтения (и выборочного изменения) данных модели без ручного экспорта и макросов.

Этот сервер — такой мост через **Model Context Protocol**: стандартный способ для Claude, Cursor и других MCP-клиентов вызывать типизированные инструменты к открытой модели Tekla.

**Что уже можно делать:**

- Проверять подключение, имя модели, количество объектов и какой сервер и какая сборка Tekla ответили
- Фильтровать и искать детали по типу, классу, профилю, материалу и имени
- Фильтровать по UDA и произвольным атрибутам — в том числе по ещё пустым UDA — и искать имя атрибута по значению
- Считать вес и количество с единым набором фильтров, потоково и постранично на моделях от 400 тыс. объектов
- Группировать метрики по полю (тип, класс, профиль, материал, имя, марка сборки, любой UDA или атрибут)
- Строить разбивку по материалам (ведомость металла)
- Узнавать, какие UDA реально есть в модели; читать каталоги окружения (профили, материалы, компоненты, определения UDA) и расширенные параметры
- Читать точную геометрию: тела деталей с вырезами, дуги гнутых элементов для размеров, габариты, оси, объекты опорных IFC-моделей
- Видеть модель: снимки живого вида Tekla и нумерованные схемы, которые рисует сам сервер
- Гонять большие объёмы через файлы: выгрузка деталей и IFC-объектов с геометрией, запись UDA из файла по GUID
- Анализировать узлы: компоненты на детали или вдоль оси, уникальные типы соединений для профиля
- Читать текущее выделение в UI Tekla и выделять объекты по фильтру
- Создавать, изменять и удалять детали, соединения и компоненты-плагины; сохранять и переключать модели — с preview по умолчанию и явным итогом записи
- Читать и записывать UDA с безопасным preview по умолчанию
- Выполнять проверенные политикой C#-скрипты, когда подходящего инструмента нет
- Искать, проверять, создавать, обновлять, выпускать и печатать чертежи, править виды и содержимое *(экспериментально)*

## Архитектура

Сервер написан на **C#**, потому что Tekla Open API поставляется как .NET-сборки (`.NET Framework 4.8`, x64). Все MCP-инструменты зависят от одной абстракции — `ITeklaModelService` — с двумя реализациями:

| Реализация | Сборка | Назначение |
|---|---|---|
| `MockTeklaModelService` | `net8.0` | Синтетический стальной каркас (43 объекта, включая гнутую арку `PolyBeam`) для разработки без Tekla |
| `TeklaModelService` | `net48` (Windows) | Данные из открытой модели (проверено на Tekla 2021 и 2023) |

Подробнее — [docs/architecture.md](docs/architecture.md) (на английском).

### Безопасность записи

Все записывающие инструменты по умолчанию работают в режиме **preview** (`apply=false`): возвращают
план и ничего не меняют; для применения передайте `apply=true`. Созданные и изменённые объекты
помечаются UDA `MCP_ORIGIN`, закоммиченные изменения откатываются Ctrl+Z.

Каждый результат записи сообщает, что произошло и куда:

- `outcome`: `planned` (preview), `not_written`, `committed`, `partial` (закоммичено, часть
  элементов отклонена — см. `errors`) или `unknown`. Транзакций в Open API нет, поэтому сбой после
  начала записи (обрыв соединения, неудачный коммит) даёт `unknown` — ошибку инструмента с полным
  результатом (GUID, счётчики): объекты нужно перечитать, а не повторять запись вслепую.
- `target`: имя и путь модели, куда ушла запись, и PID и время старта Tekla, если экземпляр можно
  однозначно определить.
- `expectedModelPath` (необязательный, у всех записывающих инструментов и у `tekla_run_csharp`):
  папка модели (или её `.db1`), для которой предназначена запись, например `modelPath` из
  `tekla_get_connection_info`. Если в подключённой Tekla открыта другая модель, вызов отклоняется
  до записи. Рекомендуется всегда, когда открыто несколько Tekla или моделей.

Мутации из скриптов требуют `allowMutations=true` — по контракту агент сначала проверяет скрипт
через `tekla_check_csharp`, показывает его оператору и получает явное согласие. Затем
`tekla_run_csharp` вызывается с `expectedSha256` = `codeSha256` из проверки: скрипт, изменённый
после одобрения, отклоняется без компиляции и выполнения (новое в 0.8.0).

### Обмен через файлы

Ответ инструмента — это контекст языковой модели, и геометрическая сверка в него не помещается:
из модели нужно вынести десятки тысяч деталей с геометрией, а вернуть — десятки тысяч пар
GUID → значение UDA. Три файловых инструмента гоняют эти данные через файл на диске, а в ответе
возвращают только счётчики.

Путь обязан быть абсолютным, с расширением `.jsonl` / `.csv` / `.json` / `.txt`, и лежать под
разрешённым корнем. Корни задаются переменной `TEKLA_MCP_FILE_ROOT` (через `;`); если она не задана —
это `%LOCALAPPDATA%\TeklaMcp\exchange` **плюс папка открытой модели**. Заданная переменная
**заменяет** умолчания, то есть список можно сузить. UNC/device-пути, шаблоны, зарезервированные
имена устройств и выход через `..` отклоняются. У скриптового escape hatch файлового доступа нет
совсем. Единственный другой инструмент, который пишет файл по указанному агентом пути, —
`tekla_export_drawings_pdf`: он печатает через Tekla в явно заданный абсолютный `outputFile`
(preview по умолчанию, без перезаписи, пока не передан `overwrite=true`), и этот путь под
разрешённые корни не попадает.

Клиент MCP обрывает запрос примерно через 60 с, и ответ теряется, даже если сервер доработал.
Поэтому передавайте `maxObjects` (с `solidAabb` безопасная страница — около 30 000) и, пока
`truncated=true`, повторяйте вызов с `cursor=nextCursor` и `append=true`. Каждый вызов дополнительно
пишет те же счётчики в `<path>.status.json` — по нему видно, что выгрузка завершилась.

```text
tekla_export_reference_objects_file  → геометрия КМД в файл
tekla_export_parts_file              → детали КМ (например udaName=USER_FIELD_1, udaIsEmpty=true)
        …сопоставление офлайн…
tekla_set_udas_from_file apply=false → проверка matched/updated/skippedNonEmpty/notFound
tekla_set_udas_from_file apply=true  → запись
```

`overwriteNonEmpty=false` по умолчанию: UDA, в которых уже что-то есть, не перезаписываются —
решения, принятые человеком, трогать нельзя.

> ⚠️ **`includeFaceAabb` по умолчанию выключен.** Точный AABB объектов опорной модели берётся
> внутренним, версионно-хрупким вызовом Tekla. Прогон по IFC-подложке на Tekla 2021 (модель 3155,
> 13.08.2026) **повесил саму Tekla**: ядро занято, интерфейс не отвечает, а убийство MCP-клиента
> не помогло — работа к тому моменту уже была отдана в Tekla. `maxObjects`/`maxSeconds`
> останавливают скан *между* объектами и не могут прервать вызов, который не возвращается.
> На незнакомой опорной модели сначала пробуйте `maxObjects=5`. Режим по умолчанию использует
> оценку положения из IFC-файла, и каждая строка честно помечена через `aabbSource`.

- [.NET SDK 8+](https://dotnet.microsoft.com/download)

## Быстрый старт

### Windows — установка из GitHub Release (рекомендуется)

Каждый релиз содержит **отдельный zip под каждую версию Tekla** — скачайте тот, что соответствует *вашей* Tekla:

1. Откройте **[Releases](https://github.com/tempalg1n/tekla-mcp-server/releases)** и скачайте zip своей версии: `TeklaMcp.Server-vX.Y.Z-tekla2021.zip` … `-tekla2026.zip` (например, для Tekla Structures 2023 — `…-tekla2023.zip`).
2. Распакуйте архив в папку (все `.dll` должны остаться рядом с `.exe`).
3. Откройте модель в Tekla Structures и укажите в MCP-клиенте путь к `TeklaMcp.Server.exe` (см. [Подключение MCP-клиента](#подключение-mcp-клиента)).
4. Попросите ассистента вызвать `tekla_get_connection_info`: он покажет открытую модель, версию Tekla, под которую собран zip, и откуда загружены сборки Tekla.

Больше ничего настраивать не нужно: офлайн-справочник API для скриптовых инструментов сервер сам сгенерирует из вашей Tekla при первом обращении. Попробовать сервер без Tekla можно с `TeklaMcp.Server-X.Y.Z-net8.0-mock.zip` (нужен .NET 8 runtime; `dotnet TeklaMcp.Server.dll`).

> **Почему zip под каждую версию?** Протокол Tekla Open API привязан к версии, поэтому сервер собирается под конкретную Tekla. DLL самой Tekla в архив не входят — они подгружаются из вашей установленной Tekla; при несовпадении версий сервер сразу сообщит, какой zip нужен. Если папка Open API не находится автоматически, задайте `TEKLA_BIN_DIR` (см. [Настройка](#настройка)).
>
> **MCP-клиент можно запускать раньше Tekla** (Tekla 2021–2023): пока Tekla не опубликовала канал, инструменты отвечают «not reachable … nothing was sent to Tekla» и начинают работать, как только модель открыта, — без перезапуска сервера. **Перезапуск Tekla тоже не страшен** (2021–2023; принято вживую на Tekla 2023 на трёх перезапусках, на 2021 ещё не прогонялось): следующий вызов замечает мёртвое соединение и переподключается к тому же каналу (`tekla_get_connection_info` показывает `lastReconnect`). Повторов нет, поэтому запись никогда не выполняется дважды. Вызов, который переподключается, пока Tekla ещё открывает модель, ждёт её (до ~70 с по замерам), так что клиент может оборвать именно этот вызов — следующий пройдёт. Перезапуск сервера нужен только если Tekla вернулась под другим именем сессии или экземпляра (например, второй экземпляр), а также на Tekla 2024+.
>
> **Сервер завершается вместе со своим MCP-клиентом** (Windows) — когда процесс, который его запустил, исчез, или когда остановка зависла на 10 с (вызов Tekla нельзя отменить). Если ваш запускатель завершается, но держит stdio сервера открытыми, задайте `TEKLA_MCP_EXIT_WITH_PARENT=0`.
>
> **Пользователи Tekla 2024–2026: очень ждём тестов и issue.** Zip-ы под 2024+ собраны против официальных пакетов Open API, но у мейнтейнеров нет установленной 2024+. Эти версии общаются с сервером через другой транспорт (Trimble.Remoting вместо named pipes), поэтому защита соединения и автоматическое переподключение там пока не работают, а всё, что связано с подключением, не проверено. Если вы работаете в 2024, 2025 или 2026, пожалуйста, [откройте issue](https://github.com/tempalg1n/tekla-mcp-server/issues): что заработало, а что нет — больше всего помогают вывод `tekla_get_connection_info` и stderr-лог сервера. Черновик может подготовить агент через `tekla_report_gap`.

### Windows — сборка из исходников

```powershell
# Укажите TeklaVersion своей Tekla (версия NuGet-пакета; точные строки — в docs/releasing.md):
dotnet build TeklaMcp.sln -c Release -p:TeklaVersion=2023.0.1
dotnet run --project src/TeklaMcp.Server -f net48 -c Release
```

### Настройка

Все настройки — необязательные переменные окружения (блок `env` клиента или системное окружение).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TEKLA_BIN_DIR` | авто: запущенный процесс Tekla, затем реестр | Папка Tekla Open API (с `Tekla.Structures.Model.dll`: `nt\bin\plugins` на 2021, `bin` на 2023); подойдёт и родительская папка, и корень установки. Папка без этой DLL игнорируется с предупреждением |
| `TEKLA_MCP_CHANNEL` | авто по каналам, которые публикует Tekla (2021–2023); на 2024+ — имена самой Tekla | Точное имя канала (pipe) модели, если автоподбор ошибся; каналы base и Drawing подстраиваются под него |
| `TEKLA_MCP_FILE_ROOT` | `%LOCALAPPDATA%\TeklaMcp\exchange` + папка открытой модели | Разрешённые корни для файлового обмена через `;`; заданное значение заменяет умолчания |
| `TEKLA_MCP_EXIT_WITH_PARENT` | включено (Windows) | `0` — не завершать сервер, когда завершился запустивший его процесс |
| `TEKLA_MCP_API_REF_DIR` | генерируется при первом обращении, кэш в `%LOCALAPPDATA%\TeklaMcp\api-reference` | Папка с готовым справочником Open API (`*.md`); приоритетнее кэша |
| `TEKLA_MCP_SCRIPT_REF_DIR` | не задана | Только мок: папка с `Tekla.Structures*.dll`, чтобы `tekla_check_csharp` мог компилировать, а справочник API генерировался без Tekla |
| `TEKLA_MCP_USE_MOCK` | не задана | `1` — принудительно мок-бэкенд в Windows-сборке (`net48`) |
| `TEKLA_MCP_ISSUES_URL` | страница нового issue этого репозитория | Куда ведут черновики `tekla_report_gap`, например во внутренний трекер |

## Известные ограничения

- **Tekla 2024, 2025 и 2026 собраны, но не проверены — нужны тестировщики и issue.** У мейнтейнеров
  нет установленной 2024+. Эти версии используют Trimble.Remoting вместо named pipes, поэтому защита
  соединения и переподключение после перезапуска Tekla там не работают (при потере соединения нужен
  перезапуск сервера), а работа с каналами основана только на декомпилированных сборках.
- **Несколько запущенных экземпляров Tekla одной версии** пока нельзя выбирать: сервер привязывается к
  одному и сам на другой не переключается. Передавайте `expectedModelPath` при записи — тогда запись
  в чужую модель будет отклонена.
- **Ещё не прогонялось на живой Tekla** в этом релизе: переподключение на Tekla 2021, итог записи
  `unknown`, `tekla_get_part_solid`, `tekla_save_model` / `tekla_open_model`, `tekla_create_component`
  с настоящим плагином и определения UDA с `details=true`. Что проверено вживую — указано по пунктам в
  [CHANGELOG.md](CHANGELOG.md).
- **Слой чертежей экспериментальный** (появился в v0.7.0, мало полевых испытаний).
- **`tekla_render_schematic` — бета**: упрощённая геометрия, на плотных моделях картинка может быть
  перегружена.
- **Сканы всей модели ограничены таймаутом клиента (~60 с)**, а не сервером — используйте
  `maxObjects` + `cursor`. Даже подсчёт без фильтров (`tekla_count_objects`) на одной живой модели
  Tekla 2023 занял ~20 с.
