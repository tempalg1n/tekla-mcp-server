## Tekla MCP Server v0.8.1

A hotfix for the first Tekla 2026 field report: v0.8.0 could not connect to Tekla 2026 at all. It
also ships the Codex plugin card the same reporter asked for. No tools were added, removed or
changed (116 in total).

### Fixed — Tekla 2026 could not connect ([#17](https://github.com/tempalg1n/tekla-mcp-server/issues/17))

The Tekla 2026 install keeps `Tekla.Structures.dll` only in `bin\Net48Runtime`, while its
dependencies `Trimble.Remoting` and `DotNetKit` stay in `bin`. v0.8.0 looked in `bin` only, and only
for `Tekla*` names: the first call failed with `FileNotFoundException: Tekla.Structures`, and with
that worked around, the connection failed on `Trimble.Remoting`.

- The server now searches `bin` and `bin\Net48Runtime`, and supplies any assembly the Open API needs
  from the Tekla install — outside the `Tekla*` names only when the file is exactly the requested
  assembly (same name and signer, at least the requested version).
- `tekla_get_connection_info` lists the Tekla assemblies that could not be loaded and where they
  were looked for (`assemblyLoadProblems`, `teklaAssemblyFolders`), and connection errors lead with
  them instead of asking whether Tekla is running.
- On Tekla 2026 the offline API reference behind `tekla_search_api` was generated without
  `Tekla.Structures` (no `Point`, `Vector`, `Identifier`) while its status said "ready". It is now
  complete, the status warns when the Geometry3d pages are missing, and references cached by v0.8.0
  are regenerated once on first use.

If you added `codeBase` entries to `TeklaMcp.Server.exe.config` as a workaround, they are no longer
needed: a fresh v0.8.1 folder comes with the original config.

### Added — a Codex plugin card ([#18](https://github.com/tempalg1n/tekla-mcp-server/issues/18))

Every Windows zip now contains a `codex` folder. `Install-CodexPlugin.ps1` builds a **Tekla MCP**
card for your computer: one MCP server `tekla<year>` per installed Tekla version, each with its own
switch.

1. Unpack the zips for your Tekla versions side by side, e.g.
   `C:\MCP\TeklaMcp.Server-v0.8.1-tekla2021` and `C:\MCP\TeklaMcp.Server-v0.8.1-tekla2026`.
2. Run `powershell -NoProfile -ExecutionPolicy Bypass -File C:\MCP\TeklaMcp.Server-v0.8.1-tekla2026\codex\Install-CodexPlugin.ps1`.
3. Quit the Codex app completely (also from the system tray), start it again and open a new thread.

The script writes the machine-specific paths itself and installs the card with the Codex CLI. It
then lists MCP servers with the same names defined elsewhere — a direct `[mcp_servers.tekla2026]`
entry replaces the card's server even when it is disabled — and `-RemoveConflicts` removes them.
Details: [README → Codex (plugin card)](https://github.com/tempalg1n/tekla-mcp-server/blob/v0.8.1/README.md#codex-plugin-card).

### Validation

- Mock-only automated suite: 479 tests. The MCP stdio smoke passes against the 0.8.1 server
  (116 tools).
- The full solution compiles against all six Tekla packages (2021.0.0, 2022.0.10715, 2023.0.1,
  2024.0.4, 2025.0.0, 2026.0.3).
- The 2026 layout was reproduced with real Tekla 2023 files laid out like it (Tekla assemblies in
  `Net48Runtime`, their non-Tekla dependencies in `bin`): v0.8.0 fails every load across the two
  folders, v0.8.1 resolves them all and reports a missing assembly with the folders it searched.
- Live and read-only on Tekla 2021: connection, object list, model summary, `tekla_check_csharp`
  and the API reference (regenerated: 1 740 types including Geometry3d), with
  `assemblyLoadProblems` empty.
- The Codex card was generated, installed and resolved with the Codex CLI 0.153.4 in an isolated
  `CODEX_HOME` (defaults, `-Years`, conflicts, `-RemoveConflicts`, `-NoInstall -UseMock`), and a
  card server started from its `.mcp.json` connected to the live Tekla 2021.
