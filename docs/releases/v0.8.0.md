## Tekla MCP Server v0.8.0

A field-report release. Every group of changes below answers a problem observed by agents
working on live models (Tekla 2021, 2023 and 2025): whole-model analytics that needed ~20 calls
and manual scripting, bulk data that could only travel through the LLM context, curved members
that could not be dimensioned exactly, agents that never saw the model they were changing, mass
connection edits done one call at a time, and a server that had to be restarted whenever Tekla
was. 16 new tools (116 in total), none removed or renamed.

> **Tekla 2024, 2025 and 2026 builds are compiled but untested — testers wanted.** The
> maintainers have no 2024+ install. Those versions use a different remoting transport, so the
> connection guard and the reconnect after a Tekla restart are not active there. If you run
> 2024+, please [open an issue](https://github.com/tempalg1n/tekla-mcp-server/issues) with the
> `tekla_get_connection_info` output and the server's stderr — `tekla_report_gap` drafts one.

### Highlights

- **Agents can see the model.**
  - `tekla_capture_view` returns a screenshot of the live Tekla view as an image, optionally
    zoomed to target objects coloured red (optionally numbered) with the rest ghosted; camera and
    colours are restored afterwards. Pixels come only from Tekla's own view window (`PrintWindow`,
    ~25 ms on Tekla 2023) — the server never copies the screen.
  - `tekla_render_schematic` (**beta**) draws a numbered plan/elevation/iso of focus objects with
    real grid labels, levels, mm ticks and a scale bar, plus a legend mapping every number to a
    GUID. No Tekla UI involved; identical on the mock.
- **Bulk data goes through a file, not the response.** `tekla_export_parts_file`,
  `tekla_export_reference_objects_file` and `tekla_set_udas_from_file` stream jsonl/csv with
  opt-in fields (solid AABB, points, contours, UDAs), cursor pages, a `maxSeconds` budget and a
  `<path>.status.json` sidecar so a finished export survives a client timeout. Paths are limited
  to an allow-list (`TEKLA_MCP_FILE_ROOT`; default `%LOCALAPPDATA%\TeklaMcp\exchange` plus the
  open model's folder). Live on Tekla 2021: 45 082 parts with `solidAabb` in 3 pages, 216 s.
- **Whole-model analytics without materializing objects.** Weight/distinct-value analytics
  stream one key + `WEIGHT` per object, default to physical parts, page with
  `maxObjects`/`cursor`, and group by any UDA or attribute (`groupBy: 'uda:USER_FIELD_1'`).
  `tekla_discover_udas` inventories the UDAs that actually exist; `udaIsEmpty` finds the work
  queue of objects whose UDA is still blank.
- **Exact curve geometry (issue #15).** `tekla_get_part_curve_geometry` returns a PolyBeam's true
  lines and arcs (center, radius, sweep, arc length, chord, sagitta; inner/outer arcs for round
  sections), optionally in the coordinates of an active drawing view, ready for radius and curved
  dimensions. The script escape hatch no longer fails every compile on Tekla 2025 with `CS0009`
  (native DLLs are kept out of the references; checked against a Tekla 2023 bin, confirmation on
  2025 pending from the reporter).
- **Connections and orientation in bulk.** `tekla_modify_parts` (up to 200 parts),
  `tekla_modify_connections` (UpVector, auto-direction, attributes file — without delete and
  re-create), `tekla_find_connections` (across parts, selection or a box, with a per-name count)
  and `replaceExisting` on connection creation/copy. Connection `UpVector` writes that Tekla
  silently discarded now persist, and write results show the committed model, not the in-memory
  object.
- **Surviving Tekla restarts (Tekla 2021–2023).** A dead connection is replaced in-process at the
  start of the next tool call — nothing is retried, no write is repeated. Accepted on Tekla 2023
  with three real close/reopen cycles. A tool call made before Tekla is up no longer poisons the
  process. The server exits with the MCP client that launched it (`TEKLA_MCP_EXIT_WITH_PARENT=0`
  turns this off), and every tool reports a lost connection with cause and action instead of a
  raw remoting error.
- **Writes say what happened and where.** Every write result carries `outcome` (`planned`,
  `not_written`, `committed`, `partial`, `unknown`) and `target` (model name/path, Tekla PID when
  it can be told apart). `expectedModelPath` on every write tool and on `tekla_run_csharp`
  refuses the call before anything is written if Tekla has another model open. Edits and deletes
  that Tekla refused no longer count as done.
- **Component development primitives.** `tekla_create_component` (plugin/custom/system
  components with an ordered input list, read back with their children), `tekla_save_model` /
  `tekla_open_model`, `tekla_get_part_solid` (faces, loops, vertices, capped),
  `tekla_list_catalog` (profiles, materials, components, UDA definitions) and
  `tekla_get_advanced_options`.
- **The offline API reference builds itself.** `tekla_search_api` / `tekla_get_api_doc` no longer
  need a manually generated folder: the server generates it from the installed Tekla on first use
  (~7 s on Tekla 2021) and caches it per Tekla build under `%LOCALAPPDATA%\TeklaMcp\api-reference`.
- **A safer script escape hatch.** Mutating scripts are bound to the approved source; return
  values flag every truncation, include public fields (Tekla points and tuples come back as
  data), and catalog imports / model switching count as mutations.

### Upgrade notes — behavior that changed

- **Mutating scripts need `expectedSha256`.** `tekla_run_csharp` with `allowMutations=true` must
  pass the `codeSha256` that `tekla_check_csharp` returned for the script the user approved; a
  missing or stale hash is refused. Read-only runs are unaffected.
- **Script return values changed shape.** Tekla `Point`/`Vector` are now `{"X":…,"Y":…,"Z":…}`
  instead of a culture-formatted string; tuples are `{"Item1":…,"Item2":…}`; nesting goes 6 levels
  deep (was 4) with an explicit marker at the cap; `returnValueTruncated` tells whether anything
  was cut.
- **Analytics default to physical parts** (`partsOnly=true`); pass `partsOnly=false` to include
  bolts, welds and assemblies as before.
- **`tekla_find_attributes_by_value` returns an object** with scan coverage (`scannedObjects`,
  `candidatesTried`, `truncated`, `message`) instead of a bare list.
- **`tekla_get_model_summary` reports `totalWeightKg: null`** (not `0`) when weights are skipped.
- **No connection is an error, not an empty list.** Drawing list tools and `tekla_list_grids`
  (with `tekla_resolve_point` and the grid-based generators) used to answer `[]` without Tekla.
- **Grids are read, not invented.** Labels come from the model, each grid uses its own coordinate
  system, and X/Y are read as spacings. Points resolved from grid labels on models with an offset
  or second grid differ from v0.7.0 — the old values were wrong.
- **Write results gained `outcome` and `target`**, and an `unknown` outcome (a failure after
  writing began) is a tool error that still carries the full result — read back before retrying.

### A note on v0.7.0

The v0.7.0 binaries already contained the fixes for its first two field reports (writes failing
with a `ModuleManager` type-initializer exception; IFC placement fallback, `.ifczip` support and
the Renga unit fix in `tekla_get_reference_geometry`; `DetailMark` enumeration; wrapper-error
flattening). They were listed as unreleased until now and have been moved to the 0.7.0 section of
the [CHANGELOG](https://github.com/tempalg1n/tekla-mcp-server/blob/v0.8.0/CHANGELOG.md).

### Validation

- 116 unique `tekla_*` tools (51 drawing-specific); 16 added since v0.7.0, none removed.
- Mock-only automated suite: 433 tests. MCP stdio smoke (initialize, tools/list, queries) passes
  against the 0.8.0 server.
- Full solution compiles with 0 warnings against all six Tekla packages (2021.0.0, 2022.0.10715,
  2023.0.1, 2024.0.4, 2025.0.0, 2026.0.3).
- Live on Tekla 2023: reconnect acceptance (three close/reopen cycles), `tekla_capture_view`,
  the connection `UpVector` / `Position` quirks, `tekla_get_advanced_options`, arc semantics of
  `GetCenterLinePolycurve()` behind `tekla_get_part_curve_geometry`, schematic context/geometry
  reads.
- Live on Tekla 2021: `tekla_export_parts_file` acceptance (`tekla_set_udas_from_file` in preview
  only), script references, API reference generation.

### Not yet run live

- Anything on Tekla 2024, 2025 and 2026, apart from what the issue #15 reporter confirms on 2025.
- The reconnect on Tekla 2021; the `unknown` write outcome; `tekla_set_udas_from_file` with
  `apply=true`; `tekla_get_part_solid`;
  `tekla_save_model` / `tekla_open_model`; `tekla_create_component` with a real plugin;
  `tekla_list_catalog` UDA definitions with `details=true`.
- The drawing-view coordinates of `tekla_get_part_curve_geometry` (no drawing was open during the
  live run).

### Known limitations

- `includeFaceAabb` on `tekla_export_reference_objects_file` ships **off**: on Tekla 2021 it left
  Tekla itself unresponsive across an IFC overlay. Probe with `maxObjects=5` before enabling it.
  `maxSeconds` bounds many slow objects, not one Open API call that never returns.
- With several Tekla instances of the same version, the server binds to one and never switches;
  explicit instance selection is not implemented yet.
- The reconnecting call waits while Tekla is still opening the model (up to ~70 s measured), so an
  MCP client may time out on that one call; the next one works.
- An unfiltered `tekla_count_objects` took ~20 s on a Tekla 2023 model, against the documented
  "instant"; under investigation (see
  [docs/backlog.md](https://github.com/tempalg1n/tekla-mcp-server/blob/v0.8.0/docs/backlog.md)).
- The drawing layer remains **experimental** and `tekla_render_schematic` is **beta**.
