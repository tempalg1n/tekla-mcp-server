## Tekla MCP Server v0.9.0

Field fixes from Tekla 2021 audit and drawing sessions (curved monorail plans, truss node sheets),
a read-only numbering status, curved Beams in the curve tool, and a round of drawing features:
mark contents and custom marks, view labels, standalone callouts, view-coordinate geometry, GA views
placed by their frame, and a picture of the open drawing so agents can check their own edits. Every
tool now carries MCP annotations, and the server can run read-only or with fewer toolsets. Four
tools added (120 in total, 54 for drawings).

**Save your drawings.** A write to the open drawing that says `committed` is not saved — Tekla drops
unsaved drawing edits when the model is reopened. Results now say `drawingSaved=false`; save with
`tekla_save_drawing` after each milestone ([#41](https://github.com/tempalg1n/tekla-mcp-server/issues/41)).

### Fixed

- **Numeric UDAs read as blank** ([#21](https://github.com/tempalg1n/tekla-mcp-server/issues/21)).
  On Tekla 2021 every `GetUserProperty` overload answers true for a set UDA, and the string one gives
  `""` for numbers. The server tried the string first, so integer UDAs exported as blanks, matched
  `udaIsEmpty` and could be overwritten by an import that was told to keep non-empty values. UDAs are
  now read and written by the type the catalog declares. On a live model the difference is large:
  `tekla_count_objects type=Beam udaName=cm_kat udaIsEmpty=true` answers 31 122 (every beam) on
  v0.8.1 and 7 394 on v0.9.0. A string UDA now keeps `"123"` a string when written, and a value that
  does not fit a declared number is refused before anything is written.
- **`tekla_modify_parts` reported edits Tekla did not store** ([#22](https://github.com/tempalg1n/tekla-mcp-server/issues/22)).
  Every written part is read back and compared with the request; `verification` lists each field
  whose stored value differs, and a mismatch makes the outcome `partial`. Capped previews say so
  (`previewTotal`, `previewTruncated`).
- **Straight dimensions sat on the parts** ([#26](https://github.com/tempalg1n/tekla-mcp-server/issues/26)):
  `distance` is paper mm again (multiplied by the view scale). If you passed `paper mm × scale` as a
  workaround, pass paper mm now.
- **Radius dimensions drew the complementary arc** ([#27](https://github.com/tempalg1n/tekla-mcp-server/issues/27)):
  points given counter-clockwise are reordered for Tekla, with a warning.
- **A closed model looked empty** ([#25](https://github.com/tempalg1n/tekla-mcp-server/issues/25) §8):
  `tekla_get_connection_info` has `modelOpen`, and model scans refuse while no model is open.
- **Section views ignored their attribute file** ([#34](https://github.com/tempalg1n/tekla-mcp-server/issues/34)):
  it is loaded after creation now (sections, curved sections, detail views), keeping name, scale,
  label and restriction box; `depthUp` (behind the cut) and `depthDown` (toward the viewer) must be
  > 0, and the preview says where the section looks.
- **Dimension distances read back in view units** ([#26](https://github.com/tempalg1n/tekla-mcp-server/issues/26)):
  they double after a 1:5 → 1:10 rescale while the line stays put on paper; listings also give
  `dimensionDistancePaperMm`. New `placing=fixed` keeps a line exactly where it was asked to go.

### Added

- **`tekla_capture_drawing`** ([#31](https://github.com/tempalg1n/tekla-mcp-server/issues/31)) — a
  picture of the open drawing as Tekla draws it: the whole sheet, one view's frame or a sheet region,
  with each view's frame and pixel box and a pixel → sheet-mm mapping. Agents can check their own
  dimensions, marks and labels instead of asking for a screenshot. Read-only: the pixels come from
  Tekla's own drawing window, and nothing is zoomed or selected. When the editor is zoomed in past the
  sheet's edges, the whole window comes back without coordinates (`scope="visible"`).
- **`tekla_get_numbering_status`** ([#23](https://github.com/tempalg1n/tekla-mcp-server/issues/23)) —
  whether numbering is up to date, for the model and for up to 200 GUIDs, without any write
  permission. Scripts may call `Operation.IsNumberingUpToDate(All)` / `IsNumberingAllowed` read-only.
- **Curved Beams in `tekla_get_part_curve_geometry`** ([#30](https://github.com/tempalg1n/tekla-mcp-server/issues/30)) —
  one exact arc through the centerline (radius, sweep, arc length, chord, sagitta, view block).
- **Mark content in `tekla_list_drawing_objects`** ([#32](https://github.com/tempalg1n/tekla-mcp-server/issues/32)) —
  what each mark shows, the marked model object, and `emptyMarksOnly` to find empty marks.
- **GA views placed by frame** ([#33](https://github.com/tempalg1n/tekla-mcp-server/issues/33)) —
  `placeBy=frame_lower_left|frame_center`; views report `frameMin`/`frameMax`.
- **View attribute files on existing views** ([#28](https://github.com/tempalg1n/tekla-mcp-server/issues/28)) —
  `tekla_modify_drawing_view attributeFile` keeps scale, restriction box, origin, label and name and
  reports the view's model-object count before and after.
- **View labels** ([#35](https://github.com/tempalg1n/tekla-mcp-server/issues/35)) — `labelText`,
  font, height and position on `tekla_modify_drawing_view`, `renameMark` for the linked
  section/detail mark, and `labelText` in `tekla_list_drawing_views`.
- **Standalone callouts** ([#36](https://github.com/tempalg1n/tekla-mcp-server/issues/36)) —
  `tekla_create_detail_mark` and `tekla_create_section_mark` without creating a view.
- **Custom marks** ([#37](https://github.com/tempalg1n/tekla-mcp-server/issues/37)) — leader start,
  placing, own text or content copied from another mark, on new and existing marks.
- **Geometry in view coordinates** ([#38](https://github.com/tempalg1n/tekla-mcp-server/issues/38)) —
  `includeModelGeometry` gives parts a solid-vertex box with its depth range and bolts their
  positions; filter by `zRange`, `region`, name or profile. Dimension sets list their points.
- **Mark offsets kept on rescale** ([#39](https://github.com/tempalg1n/tekla-mcp-server/issues/39)).
- **Scripts approved by reference** ([#40](https://github.com/tempalg1n/tekla-mcp-server/issues/40)) —
  run a checked script by `checkId` instead of sending it a third time; the hash ignores line
  endings and trailing whitespace.
- **MCP tool annotations on every tool.** 50 tools are `readOnlyHint=true`; the other 70 also say
  whether they can modify or delete what exists (`destructiveHint`) and whether a repeat changes
  anything more (`idempotentHint`). Clients such as Claude Desktop and Codex use them to approve
  reads without asking and to ask before writes. The hints describe what a tool can do with
  `apply=true`, not its preview default; selection, `tekla_capture_view` and `tekla_open_drawing`
  change the Tekla UI and the file exports write files, so none of them is read-only.
- **Read-only mode: `TEKLA_MCP_READ_ONLY=1`** — the server lists only the 50 read-only tools (no
  writes, no `tekla_run_csharp`, no selection, no model-view capture, no file exports) and every
  write path also refuses at runtime, so a tool annotated read-only by mistake still cannot write.
  `tekla_get_connection_info` reports `serverReadOnly`. Unset means off; any value other than
  `0`/`false`/`no`/`off` turns it on.
- **Toolsets: `TEKLA_MCP_TOOLSETS`** (`core`, `model`, `analytics`, `files`, `drawings`,
  `scripting`, `visual`; `core` is always served) — for clients that load every tool description
  into the context: the full list is about 195k characters, the 54 drawing tools about 82k. It only
  hides tools and is not a safety feature; an unknown name stops the server instead of hiding tools
  silently. See [Read-only mode and toolsets](https://github.com/tempalg1n/tekla-mcp-server/blob/v0.9.0/README.md#read-only-mode-and-toolsets).

### Validation

- Mock-only automated suite: 643 tests. The MCP stdio smoke passes against the 0.9.0 server:
  120 annotated tools, 50 in read-only mode (write calls refused), 58 with `TEKLA_MCP_TOOLSETS=drawings`.
- The full solution compiles without warnings against all six Tekla packages (2021.0.0,
  2022.0.10715, 2023.0.1, 2024.0.4, 2025.0.0, 2026.0.3).
- Live and read-only on Tekla 2021 (model 3155) with the 0.9.0 build: connection info
  (`modelOpen=true`), typed UDA counts and distinct values (`0` kept apart from "not set"),
  `tekla_get_numbering_status`, a read-only `Operation.IsNumberingUpToDateAll()` script, the curved
  monorail (R2500, 140.93°, arc length = `LENGTH` 6 149.324 mm), a `tekla_modify_parts` preview and
  a script run by `checkId`. On an open GA drawing of the same model, read-only: view frames and
  labels, mark contents (empty marks found with `emptyMarksOnly`), dimension sets (750 view units at
  1:75 = 10 paper mm), plate geometry in view coordinates with its depth range, and model GUIDs on
  drawing parts and marks — which also fixed two listing bugs before the release (framed mark text,
  missing GUIDs). `tekla_capture_drawing` on an A2 GA sheet of the same model: as opened, zoomed
  out and zoomed in (title-block cells mistaken for the sheet edge when zoomed in were fixed before
  the release).
  The getter behaviour behind #21 and the curved-Beam centerline were measured on 300 beams and four
  monorails of the same model.

### Not yet run live

Writes were not run on a live model for this release. Every drawing write follows a recipe the
reporter ran live by script, but the tools themselves are unverified: frame placement, attribute
files on views and sections, labels and mark renames, standalone and custom marks, mark offsets on
rescale, dimension placing. Also unverified: the `tekla_modify_parts`
verification against a real refusal, the typed UDA writes, and the distance units of radius, curved
and angle dimensions (passed unchanged; angle and curved are documented as paper mm). Renaming a
detail view's mark can miss it: detail marks do not always enumerate on Tekla 2021.

The tool annotations and read-only mode are checked by the MCP smoke only: no client's approval UX
(Claude Desktop, Codex) and no live Tekla run has been checked against them yet.

### Known limitations

- Option-list UDAs come back as their raw stored numbers, not their displayed labels.
- `tekla_capture_drawing` is live-verified on Tekla 2021 only; the drawing window's title and the
  drawn sheet edge on 2022–2026 are untested.
- With a drawing open, `tekla_capture_view` without `viewName` captures the drawing window as if it
  were the active model view.
- Everything listed for [v0.8.0](https://github.com/tempalg1n/tekla-mcp-server/blob/v0.9.0/docs/releases/v0.8.0.md#known-limitations)
  still applies.
